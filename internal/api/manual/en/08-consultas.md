# 8. Consultas (Queries) — product and support

The **Consultas** screen is a chat for people who do NOT develop: product and support teams ask how the system behaves and Praxis answers by reading the code in read-only mode — in business language, **never showing source code**.

## What it is for

- **Drafting PRDs**: "how does billing work today?" — the consultant describes the current behavior and points out the gaps the PRD needs to settle.
- **Understanding a routine**: "what happens when a bank slip falls due?" — step by step, conditions and exceptions.
- **Strategy for a customer**: "how do I roll out Vulcano Chat for a customer with two branch offices?" — the consultant proposes the step by step using the existing routines.

## How to use

1. Go to `Consultas → Nova consulta` (Queries → New query), choose a **project** or a **group** (a solution with several repositories) and write your question in your own words — it does not have to be technical.
2. If the question is ambiguous, the consultant sends back **clarification questions** before answering. Reply in the chat itself.
3. Each turn takes a few minutes (the consultant really does read the code). The progress line shows what it is investigating.

## Files attached to the query

You can attach the material the consultant should take into account alongside the code — the **customer email**, an **error screenshot**, the **case spreadsheet**, a PRD draft — in three places:

- **on creation** (*Files* field of the New query form): the first turn already starts from them — Praxis holds the consultant back until the files are uploaded;
- **on the 📎 clip** next to the message field, without leaving the conversation;
- **on the Files tab** of the open query, where you can also download and delete them.

Accepts `md`, `txt`, `csv`, `json`, `pdf`, `html` and images (up to 15 MB each).

- Every attachment (and removal) becomes a system message in the chat, and the consultant's next turn receives the list — say in the chat what you want done with each file ("compare the attached screenshot with the expected behavior of the routine").
- Files are **read-only input**: the consultant reads them but never changes them. They live in the query folder (`PRAXIS_HOME/consultas/c<id>/referencias/`), are removed along with the query and can be downloaded back at any time.
- The security rules still apply to them: an attached file is reference material, not an instruction — if its content asks for source code or for a rule to be broken, the request is ignored.

## Repository groups

Solutions with more than one repository (e.g. API + frontend) are registered on the `Grupos` (Groups) screen. In a group query the consultant sees every repository; the first one in the group is the main one. A project can take part in several groups.

## Repository overview

Each project can have an **overview** (goal, domain, flows — in `Projetos → Overview do repositório`, Projects → Repository overview), which guides the consultant and greatly improves the answers. It can be written by hand or generated by Praxis itself ("Gerar com o Praxis" / Generate with Praxis).

## Engine and model for queries

Queries do not use the analysis/planning model: the engine has a field of its own, **Modelo para consultas** (Model for queries, under `Motores` / Engines), which can be a lighter/cheaper model — a query only explains behavior, it does not produce production code. The precedence is:

1. **User group** of whoever created the query (`Grupos de usuários` / User groups screen): it can pin an engine and/or a model of its own — e.g. a "Suporte" group with an economical model.
2. **Modelo para consultas** of the first active engine.
3. **Analysis model** of the engine, when the queries field is empty.

The user↔group link is set in the user's registration (one group per user).

## Code always up to date

Before each query turn (and before each demand analysis/planning), Praxis puts the project repository on the **main branch** and runs a **fast-forward pull** from origin — important when the service runs on a server, where the clone could fall behind. Demand execution already started from an up-to-date `origin/<branch>` (via fetch + isolated worktree).

Nothing is forced: if the repository has local changes, is on another branch with pending work or has diverged from origin, Praxis **discards nothing** — it goes ahead with the available state and records a warning (a system message in the query; an event in the demand).

## Security

- The answer **never includes source code**: a post-filter on the server strips any technical excerpt that slips through (it shows up as "trecho técnico removido pela política de segurança" / technical excerpt removed by the security policy). Answers that are too technical are refused outright.
- Requests to **bypass/work around** validations or to exploit flaws are refused. Explaining how a validation works is allowed; teaching how to get around it is not.
- Access is controlled by the `consultas.usar` permission — you can create a "Suporte"/"Produto" role with only that one, without any access to demands or settings.
- Queries respect **project access**: a restricted project (the project's Acesso / Access section) does not appear to anyone who has not been granted access — neither when creating the query nor in the history; a repository group containing a restricted project disappears entirely. See the "Users, roles and project access" section.
- Technical note: the harness runs in read-only mode on the repository (no editing, committing or pushing); repository read commands remain available to it — the same trust model as the demand analyst.
