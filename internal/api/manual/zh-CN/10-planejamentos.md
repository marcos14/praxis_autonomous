# 10. Planejamentos（规划）—— 与策略师一起产出 PRD 和 ADRs

**Planejamentos（规划）** 页面是 PM、PO 和架构师的空间：你描述一个诉求，**策略师** —— 以只读模式阅读各仓库的代码 —— 通过反复对话与你一起打磨出 **PRD**（业务视角）、**ADRs**（架构决策）或两者。产出的文档立足于系统今天真实的样子，一键就能变成需求。

## 用途

- **在提出需求之前先备好完整的 PRD**：与其把一份粗糙的 PRD 贴进 Nova demanda（新建需求），不如带着已经定好的需求点、验收标准和结论过去 —— 分析师的提问轮次更少，计划也更好。
- **用 ADRs 记录架构决策**：记录背景、决策、备选方案和后果 —— 由策略师在代码中确认真实存在的约束。
- **把计划可视化**：除了文本，策略师还会生成一份**视觉演示**（信息图、流程图）；如果你要求，还能生成所提议界面的**可交互原型** —— 在投入开发之前先对齐愿景。

## 使用方法

1. 进入 `Planejamentos → Novo planejamento`，选择一个**项目**或一个**组**、**foco（产出重点）**（PRD、ADRs 或两者）以及**视觉级别**：
   - **Documento（文档）** —— 只有 `.md`；
   - **Apresentação（演示）**（默认）—— 额外生成一个 HTML，包含执行摘要、信息图和流程图；
   - **Protótipo（原型）** —— 额外生成所提议界面/流程的可交互模拟。
2. 用你自己的方式描述诉求。如果有含糊之处，策略师会在动笔前提出**决策问题** —— 在聊天中回答即可。
3. 每一轮之后，文档会出现在 **Documentos（文档）** 标签页（带修订历史），制品出现在 **Artefatos（制品）** 标签页（在新标签页中打开）。可以在聊天里不断提出修改，直到文档打磨到位。
4. 你可以**在对话进行中改变产出重点和视觉级别** —— 下一轮就会照做。
5. 当 PRD 准备好后，点击 **Criar demanda（创建需求）**：该文档会成为一个新需求的第一条消息（有 ADRs 时会一并附上），接下来由 intake 的分析师接手。需求卡片会立刻打开，规划中也会记录**与所交付修订版本**的关联。

### 一个规划，多个需求

规划是一份活的文档，可以生成**你需要的任意多个需求** —— 从零重做、试一个变体（A/B）、在仓库组的另一个仓库中交付。顶部的 **Demandas (N)（需求 (N)）** 按钮会打开交接对话框，其中显示：

- 已经生成的需求，以及每个需求的**状态**和它收到的是 PRD/ADRs 的**哪个修订版本**；
- **drift（漂移）**：如果文档在上次交付之后又有演进，对话框会提示存在尚未交付的变更；
- **存在活跃需求时的提示** —— 从同一个计划再创建一个需求，可能产生重叠的工作（并不会被阻止：A/B 测试是合理的，而且 Kanban 会标示需求之间的文件重叠）。

在这里创建的需求始终是**完整的**（当前文档的全部内容）。**互补型**需求 —— 只包含自某次已完成的交付以来演进的部分，由策略师生成增量 PRD —— 将在后续版本中提供。

## 分步推进（产品 ↔ 架构）

规划从设计之初就是**协作、分步**进行的 —— 不需要在创建时就把一切都定下来：

1. **PO 先开始**，以 **PRD** 为重点，与策略师一起打磨文档，直到业务视角定稿。
2. **架构师在同一个规划中继续**：把 *Produzir（产出）* 字段改成 **PRD + ADRs**（或只选 ADRs），并在聊天中提出自己的要点。策略师会保持 `prd.md` 原样不动，转而产出 `adrs.md` —— 并让两者保持一致（如果某个架构决策与 PRD 相矛盾，它会指出来）。
3. 聊天中的每条发言都会显示**是谁说的**（登录用户的名字），因此整场讨论都被记录下来：哪些来自产品，哪些来自架构。
4. 两人中的任何一位（拥有 `demandas.criar` 权限）都可以在整体就绪时点击 **Criar demanda（创建需求）** —— PRD 会连同附上的 ADRs 一起过去。

反过来的顺序同样可行（架构师先、产品后），也完全可以从头到尾只做一个纯 ADRs 的规划。

## 参考资料（附加辅助文档）

你可以附上希望策略师作为基础的材料 —— 用来当模板的**另一个项目的 ADR**、作为 PRD 起点的**会议记录**、草稿、需求表格 —— 有三个地方可以上传：

- **在创建时**（Novo planejamento 表单的 *Referências（参考资料）* 字段）：第一轮就以它们为出发点 —— Praxis 会等文件上传完成后才让策略师开始；
- **在消息输入框旁的回形针 📎 处**，无需离开对话；
- **在已打开规划的 Referências（参考资料）标签页中**，在那里还可以下载和删除。

支持 `md`、`txt`、`csv`、`json`、`pdf`、`html` 和图片（每个最大 15 MB）。

- 每次附加（和移除）都会在聊天中生成一条系统发言，策略师的下一轮会收到这份清单 —— 请在聊天中说明希望它如何使用每一份材料（“把附上的 ADR-007 当作格式模板”）。
- 参考资料是**只读输入**：策略师只会查阅，绝不修改。它们保存在规划的文件夹中（子文件夹 `referencias/`），随时可以下载回来或删除。

## 文档与制品

- `.md` 是**唯一事实来源**，在数据库中做版本管理 —— 每一轮只要改动了文档就会写入一个新的修订版本，你可以重新阅读任何历史修订。
- `.html` 制品属于展示层，始终从文档重新生成。它们是**自包含文件**（离线可用，不依赖 CDN），保存在 `PRAXIS_HOME/planejamentos/p<id>/`。
- 打开制品时，它运行在**浏览器沙箱**中：制品的 JavaScript 既无法访问你的 Praxis 会话，也无法访问 API —— 它只是展示。
- 所有内容都可以**下载到你的机器上**：文档通过 *Baixar .md（下载 .md）* 按钮（下载当前显示的修订版本），制品通过 *Baixar（下载）* 按钮 —— 由于是自包含的，下载下来的 HTML 直接从硬盘打开也能正常工作，可以直接作为邮件附件或用于演示。

## 引擎与模型

规划使用与咨询相同的引擎解析方式（引擎的 **Modelo para consultas（咨询模型）** 字段；创建者所属的用户组可以固定专用的引擎/模型）。由于这是分析和写作的工作 —— 而不是生产代码 —— 通常一个更经济的模型就够用了。

## 安全

- 访问由权限 `planejamentos.usar` 控制。**注意**：与 Consultas（咨询）不同，这里**没有**反代码过滤 —— ADRs 按其定义本来就会提到组件、路径和技术。请把该权限授予可以看到架构内部细节的人。
- 策略师**绝不会修改仓库**：它运行时的写入被限制在规划的文件夹内，各仓库以只读方式接入；作为最后一道安全网，Praxis 会比较每个仓库在该轮前后的 `git status` —— 一旦检测到任何改动，该轮会立即失败，并列出这些文件供你核对（不会自动回滚任何东西）。
- 与咨询一样，规划也遵循**项目访问权限**（ACL）：受限项目不会出现在未被授权的人面前。
- 删除一个规划会移除对话、文档、制品以及工作文件夹。
