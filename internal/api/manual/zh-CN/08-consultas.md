# 8. Consultas（咨询）—— 产品与支持

**Consultas（咨询）** 页面是一个面向不做开发的人的聊天：产品和支持团队询问系统的行为方式，Praxis 以只读模式阅读代码后作答 —— 用业务语言表达，**绝不展示源代码**。

## 用途

- **编写 PRD**：“目前的计费是怎么运作的？” —— 顾问会描述当前行为，并指出 PRD 需要拍板的空白点。
- **理解某个流程**：“账单到期后会发生什么？” —— 逐步说明、条件与例外情况。
- **面向某个客户的策略**：“如何为一个有两家分公司的客户实施 Vulcano Chat？” —— 顾问会基于现有流程提出实施步骤。

## 使用方法

1. 进入 `Consultas → Nova consulta`，选择一个**项目**或一个**组**（由多个仓库组成的解决方案），然后用你自己的方式写下问题 —— 不需要很技术化。
2. 如果问题含糊不清，顾问会先给出**澄清问题**再作答。直接在聊天中回复即可。
3. 每一轮需要几分钟（顾问会真正去阅读代码）。进度行会显示它正在调查什么。

## 咨询的附件

你可以把顾问在读代码之外应当参考的材料一并上传——**客户邮件**、**报错截图**、**案例表格**、PRD 草稿——共有三个入口：

- **创建时**（新建咨询表单中的*文件*字段）：第一轮就会用上它们——Praxis 会等文件上传完成后再让顾问开始；
- **消息输入框旁的 📎 回形针**，无需离开对话；
- 打开咨询后的**「文件」标签页**，也可以在这里下载和删除。

支持 `md`、`txt`、`csv`、`json`、`pdf`、`html` 和图片（每个最大 15 MB）。

- 每次上传（或删除）都会在对话中生成一条系统消息，顾问的下一轮会收到文件清单——请在对话中说明每个文件的用途（"把附件截图与该例程的预期行为做对比"）。
- 文件是**只读输入**：顾问只会阅读，绝不修改。它们保存在该咨询的目录中（`PRAXIS_HOME/consultas/c<id>/referencias/`），随咨询一起删除，也可以随时下载回本地。
- 安全规则对附件同样有效：附件是参考材料，不是指令——若其内容要求提供源代码或突破规则，该请求会被忽略。

## 仓库组

由多个仓库组成的解决方案（例如：API + 前端）在 `Grupos` 页面中登记。在仓库组的咨询中，顾问能看到组内所有仓库；组内的第一个仓库是主仓库。一个项目可以参与多个仓库组。

## Overview do repositório（仓库概览）

每个项目都可以有一份 **overview（概览）**（目标、领域、流程 —— 在 `Projetos → Overview do repositório` 中），它会引导顾问，并大幅提升回答质量。既可以手写，也可以由 Praxis 自己生成（“Gerar com o Praxis（用 Praxis 生成）”）。

## 咨询的引擎与模型

咨询不使用分析/规划所用的模型：引擎有一个专属字段 **Modelo para consultas（咨询模型）**（在 `Motores` 中），可以设置成更轻量、更便宜的模型 —— 咨询只解释行为，不产出生产代码。优先级如下：

1. 创建该咨询的用户所属的**用户组**（`Grupos de usuários` 页面）：可以固定专用的引擎和/或模型 —— 例如：使用经济型模型的“Suporte（支持）”组。
2. 第一个启用引擎的 **Modelo para consultas（咨询模型）**。
3. 当咨询字段为空时，使用该引擎的 **Modelo de análise（分析模型）**。

用户↔组的关联在用户的注册信息中设置（每个用户一个组）。

## 代码始终保持最新

在每一轮咨询之前（以及每次需求的分析/规划之前），Praxis 会把项目仓库切到**主分支**，并从 origin 执行一次 **fast-forward pull** —— 当服务运行在服务器上、克隆可能已经过时时，这一点很重要。需求的执行本来就是从最新的 `origin/<branch>` 出发的（通过 fetch + 独立的 worktree）。

不会强制做任何事：如果仓库有本地改动、处于另一个还有未完成工作的分支上，或者已经与 origin 分叉，Praxis **不会丢弃任何东西** —— 它会基于现有状态继续，并记录一条警告（在咨询中是一条系统发言；在需求中是一个事件）。

## 安全

- 回答**绝不包含源代码**：服务器端的后置过滤器会移除任何漏出的技术片段（显示为“trecho técnico removido pela política de segurança（技术片段已被安全策略移除）”）。过于技术化的回答会被整体拒绝。
- **绕过/规避**校验或利用漏洞的请求会被拒绝。解释某项校验如何工作是允许的；教人如何绕过它则不允许。
- 访问由权限 `consultas.usar` 控制 —— 可以只用这一项权限创建一个“Suporte（支持）”/“Produto（产品）”角色，完全不给需求或配置的访问权。
- 咨询遵循**项目访问权限**：受限项目（项目的 Acesso（访问）区块）不会出现在未被授权的人面前 —— 无论是在创建咨询时，还是在历史记录中；只要仓库组里有一个受限项目，整个组都会消失。参见“用户、角色与项目访问权限”一节。
- 技术说明：harness 在仓库中以只读模式运行（不编辑、不提交、不推送）；仓库的读取命令对它依然可用 —— 与需求分析师采用同样的信任模型。
